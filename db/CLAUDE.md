# db/ rules

- `db/` owns all SQL and business logic; no `print()`/`input()`. `pdf/` and `api/` only call `db/` functions. Need a new query → add it here.
- Every write: `with transaction(conn):` (nests via savepoints). Never `commit()`, `rollback()` or `BEGIN` directly.
- "Today" only via `timeutil.today_local(conn)`, never `date.today()`/`datetime.now()`. Tests monkeypatch `today_local` in the module under test. All timezone work in `timeutil`; Jalali math in `jalali.py`.
- Money is integer Rial, never float; all money rounding is half-even to the Rial. `round()` is half-even; reconcile leftovers so totals sum exactly (see `distributions._compute_share_amounts`). Quantities may be REAL; money never.
- Raise errors from `errors.py` (`NotFoundError`, `ValidationError(field=)`, `InsufficientStockError`, `ConflictError`); the API maps them to HTTP. A refusal the UI must tell apart gets a specific `code=ErrorCode.…` and `details=` (documented on `ErrorCode`); the UI never reads the message text.
- Boolean-ish columns stay int 0/1.
- Low stock (materials only; products have no minimum): an active STOCK material with `current_stock <= 0`, or with `min_stock` set and `current_stock <= min_stock`. One rule, `materials._LOW_STOCK`, feeds `is_low_stock` on every material row and `get_low_stock_materials()` (its `threshold` argument is the legacy flat cut-off). `min_stock` is a quantity in the material's unit; NULL = none; SERVICE never has one (enforced in `db/`, not by a CHECK).
- Categories: `validate_assignable` decides placement. `products.category` is legacy; don't read it.
- `orders.record_order`: `None` shipping/postage = channel default (0 is a real zero); `transaction_fee=None` = computed from the payment method.
- Partner distributions are payouts, not expenses: distributions may read `get_profit_and_loss` but never write `orders`/`order_items`/`expenses`; no report queries `partners`/`profit_distributions`/`distribution_shares`.
- Display currency conversion (Rial → Toman) happens only in `currency.py` (guarded by `tests/test_no_money_scaling.py`); every other module works in integer Rial.
- Audit log: every public function in `db/` that writes an accounting table is decorated `@audited()` (`db/audit.py`); the triggers in the migrations do the logging. A new table or column needs its `trg_audit_*` triggers regenerated with `audit_trigger_sql` in the same migration (`tests/test_audit_triggers.py` fails otherwise); a column or table that should stay out goes in `UNAUDITED_COLUMNS` / `UNAUDITED_TABLES`, with a reason. Never write to `audit_log` yourself; clearing it is `reset_audit_log` only.
- Names: a user-typed unique name is saved as `names.stored_form(name)` with `name_key` set, inside `name_keys.duplicate_guard` (pre-check, then the unique index; error `NAME_DUPLICATE`). A new table with such a name needs `name_key`, a partial unique index, an entry in `name_keys.NAME_KEY_TABLES` and an `updated_at` trigger that fires `AFTER UPDATE OF` its business columns (not `name_key`; `tests/test_migration_013.py` checks the list). Never rewrite an existing name.
- Limits: every money input and every computed amount goes through `costing.check_money` (`round_half_even` does it for you); quantities through `costing.check_quantity`. Never let a value reach SQLite unchecked: past 2^63 it is an `OverflowError` (a 500).
- `python -m tools.integrity_check` (read-only) recomputes stored figures with the functions in `db/`; a new accounting invariant gets a check there, reusing `db/` and never copying a formula (`docs/accounting-rules.md` section 18). A needed private helper becomes a public read-only alias in `db/`.
- Voided orders (`order_voids.py`, accounting-rules section 20): a mistaken sale is voided (`void_order`) or corrected (`correct_order`), never edited. A query that lists or counts orders by status must leave VOIDED out: use the status IN-lists (`REVENUE_ELIGIBLE_STATUSES`, `PAID_STATUSES`), never `NOT IN` / `<>` on CANCELLED or REFUNDED alone; `list_orders` hides VOIDED unless `include_voided`.
- Stocktake: a count is applied only through `stocktake.apply_stocktake` (one transaction; each correction is a `record_stock_adjustment` ADJUSTMENT, `allow_inactive` is for it alone). Quantities compare as exact decimals (`exact_quantity`) rounded to 1e-9, never as floats.
- Backups: `db/backup.py` makes the daily online backup (SQLite backup API, verified, newest 60 `daily-*.db` kept, nothing else ever deleted). It reads the database and writes only into the `backups/` folder next to it; tests always use temp folders (`tests/conftest.py` fails the run if the real `data/` changed).
